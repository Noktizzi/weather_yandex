### 2. ОСНОВАНИЕ ДЛЯ РАЗРАБОТКИ

Разработка веб-приложения для предоставления пользователям актуальной информации о погодных условиях в городах Российской Федерации с возможностью сохранения избранных локаций и переключения единиц измерения температуры.

---

### 3. НАЗНАЧЕНИЕ И ЦЕЛИ СОЗДАНИЯ СИСТЕМЫ

#### 3.1. Назначение системы

Веб-приложение предназначено для:
- Получения актуальной информации о текущей погоде в городах РФ
- Просмотра прогноза погоды на 3 или 7 дней
- Просмотра почасового прогноза на текущий день
- Управления списком избранных городов
- Определения погоды по геолокации пользователя

#### 3.2. Цели создания системы

- Предоставление удобного интерфейса для мониторинга погоды
- Обеспечение быстрого доступа к погодным данным
- Персонализация опыта пользователя через избранное
- Адаптация под различные устройства (десктоп, планшет, мобильные)

---

### 4. ХАРАКТЕРИСТИКА ОБЪЕКТОВ АВТОМАТИЗАЦИИ

#### 4.1. Источник данных

**API Яндекс.Погода** (https://api.weather.yandex.ru/v2/)
- Текущая погода
- Прогноз на 7 дней
- Почасовой прогноз

#### 4.2. Справочник городов

Встроенный справочник из 51 крупнейшего города РФ с координатами (широта, долгота).

### 5. ТРЕБОВАНИЯ К СИСТЕМЕ

#### 5.1. Требования к структуре и функционированию системы

##### 5.1.1. Архитектура системы

**Клиент-серверная архитектура:**
- **Серверная часть:** Node.js + Express.js
- **Клиентская часть:** Single Page Application (SPA) на чистом JavaScript
- **Взаимодействие:** REST API

##### 5.1.2. Серверная часть (Backend)

**Технологический стек:**
- Node.js (версия ≥16.0.0)
- Express.js 4.18.2
- node-fetch 2.7.0

**Функциональные требования:**

1. **API-маршруты:**

   | Метод | Путь | Описание | Параметры |
   |-------|------|----------|-----------|
   | GET | `/api/suggest` | Автодополнение городов | `q` - поисковый запрос |
   | GET | `/api/cities` | Полный список городов | - |
   | GET | `/api/geocode` | Координаты по названию города | `city` - название города |
   | GET | `/api/reverse-geocode` | Ближайший город по координатам | `lat`, `lon` - координаты |
   | GET | `/api/combined` | Текущая погода + прогноз + почасовой | `lat`, `lon` - координаты |

2. **Кэширование:**
   - Текущая погода: 10 минут
   - Прогноз погоды: 30 минут
   - Реализация: in-memory кэш (Map)

3. **Безопасность:**
   - API-ключ Яндекс.Погода хранится только на сервере
   - Клиент не имеет прямого доступа к API-ключу

4. **Обработка ошибок:**
   - Валидация входных параметров
   - Обработка ошибок API Яндекс.Погода
   - Возврат понятных сообщений об ошибках

##### 5.1.3. Клиентская часть (Frontend)

**Технологический стек:**
- HTML5
- CSS3 (Custom Properties, Flexbox, Grid)
- Vanilla JavaScript (ES6+)
- Google Fonts (Rubik)

**Функциональные требования:**

1. **Поиск городов:**
   - Поле ввода с автодополнением
   - Поиск по подстроке (не только с начала названия)
   - Отображение до 8 подсказок
   - Навигация по клавиатуре (↑, ↓, Enter, Escape)
   - Кнопка очистки поля

2. **Геолокация:**
   - Кнопка "Моё местоположение"
   - Запрос разрешения на геолокацию
   - Определение ближайшего города из справочника
   - Индикация процесса загрузки
   - Обработка ошибок (отказ, таймаут, недоступность)

3. **Отображение текущей погоды:**
   - Название города
   - Время последнего обновления
   - Иконка погодных условий
   - Температура (текущая и ощущаемая)
   - Описание погодных условий на русском языке
   - Влажность (%)
   - Скорость и направление ветра
   - Атмосферное давление (мм рт.ст.)
   - УФ-индекс с цветовой индикацией

4. **Почасовой прогноз:**
   - Прогноз на текущий день по часам
   - Температура, иконка, вероятность осадков
   - Выделение текущего часа
   - Горизонтальная прокрутка
   - Автоматическая прокрутка к текущему часу

5. **Прогноз на несколько дней:**
   - Переключатель: 3 дня / 7 дней
   - Дата (день недели, число, месяц)
   - Иконка погодных условий
   - Дневная и ночная температура
   - Вероятность осадков
   - Описание условий
   - Время восхода и заката солнца

6. **Избранное:**
   - Добавление/удаление городов (кнопка ★/☆)
   - Максимум 10 городов
   - Отображение карточек с температурой и иконкой
   - Быстрый переход к городу по клику
   - Кнопка удаления на каждой карточке
   - Кнопка "Очистить всё"
   - Горизонтальная прокрутка списка

7. **Единицы измерения:**
   - Переключатель °C / °F
   - Сохранение выбора между сессиями

8. **Локальное хранилище (localStorage):**
   - Список избранных городов
   - Последний выбранный город
   - Выбранная единица измерения (°C/°F)
   - Количество дней прогноза (3/7)

9. **Обработка ошибок:**
   - Отображение сообщений об ошибках
   - Город не найден
   - Недоступность API
   - Ошибки геолокации
   - Автоматическое скрытие через 3 секунды (для некритичных)

10. **Индикация загрузки:**
    - Skeleton-экраны при загрузке данных
    - Анимация загрузки для кнопки геолокации

#### 5.2. Требования к интерфейсу пользователя

##### 5.2.1. Дизайн

**Цветовая схема:**
- Фон: #eef2f7 (светло-серый)
- Поверхности: #ffffff (белый)
- Границы: #dde3ec (серый)
- Текст: #1a2535 (тёмно-синий)
- Акцент: #1a6bff (синий)
- Приглушённый текст: #6b7a91 (серый)

**Типографика:**
- Шрифт: Rubik (Google Fonts)
- Начертания: 300, 400, 500, 600
- Базовый размер: 16px

**Визуальные элементы:**
- Скругление углов: 14px (карточки), 8-10px (элементы)
- Тени: 0 2px 12px rgba(26,37,53,.08)
- Плавные переходы: 0.15s

##### 5.2.2. Адаптивность

**Брейкпоинты:**
- Десктоп: > 700px
- Планшет: 600-700px

- Семантическая HTML-разметка

- Альтернативный текст для изображений
- Контрастность текста

#### 5.3. Требования к надёжности

1. **Обработка сетевых ошибок:**
   - Таймауты запросов
   - Повторные попытки (опционально)
   - Информативные сообщения об ошибках

2. **Валидация данных:**
   - Проверка параметров на сервере
   - Проверка ответов API
   - Обработка некорректных данных

3. **Кэширование:**
   - Снижение нагрузки на API
   - Ускорение отклика системы
   - Автоматическая инвалидация устаревших данных

#### 5.4. Требования к производительности

1. **Время отклика:**
   - Первая загрузка: < 2 секунды
   - Переключение между городами: < 500 мс (с кэшем)
   - Автодополнение: < 200 мс

2. **Оптимизация:**
   - Минимизация запросов к API
   - Кэширование на сервере
   - Debounce для поиска (180 мс)
   - Ленивая загрузка изображений

3. **Размер приложения:**
   - Один HTML-файл (SPA)
   - Минимальные зависимости
   - Использование CDN для шрифтов
